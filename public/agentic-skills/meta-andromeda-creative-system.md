# Meta Andromeda Creative System

## Quand utiliser ce skill
- Audit Meta Ads orienté créa/perf
- Monitoring de campagnes Meta
- Création ou itération de nouvelles créas
- Lecture d’un compte où Meta concentre vite la dépense sur quelques ads
- Diagnostic d’un compte avec beaucoup de variations mais peu d’apprentissage utile

## Idée centrale
Après Andromeda, **la créa devient le ciblage**. Le système apprend mieux quand on lui donne un message cohérent, des angles distincts, une landing page alignée et des variations construites à partir d’un winner. **Le volume brut ne remplace pas un système.**

## Principes non négociables

### 1. Volume sans structure = bruit
- Ne pas lancer "plein d’ads" juste pour tester plus.
- Chaque ad doit être traçable par : angle, hook, format, awareness level, promesse, offre.
- Si une ad gagne, il faut savoir **pourquoi** elle gagne.

**À documenter pour chaque créa :**
- angle
- format
- hook
- awareness level
- offre / promesse
- first frame / opening visual
- landing page associée

### 2. La créa est le vrai ciblage
- Réduire l’obsession du ciblage intérêt si la créa est générique.
- Ce que dit l’ad, à qui elle parle, comment elle cadre le problème = signal principal.
- Une ad générique ne sera pas sauvée par un intérêt stack sophistiqué.

### 3. La landing page fait partie du signal de ciblage
- Vérifier l’alignement ad → LP sur : promesse, audience, niveau d’awareness, ton, offre.
- Si l’ad parle à un persona et la LP à un autre, le système reçoit un signal mixte.
- En diagnostic, traiter une LP désalignée comme un problème de distribution, pas seulement de conversion.

### 4. La première frame compte comme un signal de ciblage
- En vidéo/Reels/UGC, la première seconde fait déjà du ciblage.
- Le décor, le contexte, le type de personne, l’environnement visible signalent la pertinence.
- Éviter les visuels trop neutres / studio / “blanc clinique” si le marché attend du contexte réel.

### 5. Les angles gagnants viennent du marché
Avant de produire des créas, miner :
1. avis clients
2. Reddit / forums
3. commentaires de pubs concurrentes
4. historique du compte ads

Objectif : récupérer les **phrases exactes** du client sur :
- douleur
- tentative ratée
- objection
- résultat désiré

Ne pas paraphraser trop tôt. Garder la matière première verbatim.

### 6. Mapper les ads par awareness level
Classer chaque créa dans un niveau :
1. Unaware
2. Problem aware
3. Solution aware
4. Product aware
5. Most aware

Constat fréquent : trop de créas BOF / product-aware.
Quand la fréquence monte vite, le problème peut être un manque de couverture amont, pas juste une fatigue créa.

### 7. Tester des angles à travers des formats
Ne pas seulement tester “des ads”, mais **un angle dans plusieurs formats**.
Exemple :
- même angle en static
- même angle en UGC
- même angle en carousel
- même angle en podcast-style / talking head

Lecture :
- si aucun format ne prend → angle faible
- si un seul format prend → angle OK, exécution/format variable

### 8. Construire depuis les winners
Ne pas repartir de zéro à chaque refresh.
À partir d’un winner, créer :
- même angle, autre format
- même hook, autre body
- même body, 3-5 nouvelles ouvertures
- même promesse, autre awareness entry point

Le winner est un **signal**, pas une fin.

### 9. Définir le framework de décision avant lancement
Avant mise en ligne, définir :
- seuil de spend de review
- seuil de CPA/CPL de kill
- signaux soft à surveiller
- fenêtre minimum avant décision

Éviter 2 erreurs :
- couper trop tôt
- laisser tourner trop longtemps par espoir

### 10. Ne pas juger uniquement au ROAS/CPA par ad trop tôt
En lecture de compte, considérer aussi :
- spend pris par l’ad
- CTR / hold / hook rate si dispo
- distribution réelle
- rôle probable dans le funnel

Une ad qui prend beaucoup de spend peut nourrir le système même si son ROAS isolé paraît inférieur à court terme.

## Guide de monitoring Andromeda

### Signaux à lire en priorité
- concentration de dépense par ad
- nombre d’ads qui prennent un spend significatif
- fréquence
- CTR / CPC / CPL
- cohérence angle-format-LP
- présence de near-duplicates

### Lecture pratique
- **1 ad capte >65% du spend** :
  - si CPL bon → Meta a trouvé un winner ; produire de vraies extensions du winner
  - si CPL mauvais → pool créatif trop proche ou angle dominant faible
- **Beaucoup d’ads à quasi 0 spend** :
  - possible manque de différenciation réelle
  - possible first frame faible
  - possible mismatch angle/offre/persona
- **Fréquence qui monte vite** :
  - vérifier si le compte parle surtout à des audiences product-aware / BOF
- **CTR faible dès départ** :
  - vérifier hook, first frame, douleur explicite, spécificité persona
- **Bon CTR mais mauvais CPL** :
  - vérifier alignement LP, qualification, promesse, friction formulaire

## Guide de production créa

### Structure de batch recommandée
Pour un batch, documenter chaque créa avec :
- angle principal
- awareness level
- format
- first frame
- hook line
- preuve
- CTA
- LP cible

### Répartition conseillée
- 3 à 5 angles réels
- 2 à 3 formats
- plusieurs awareness levels
- pas de micro-variations déguisées en diversité

### Ce qu’il faut éviter
- 6 créas quasi identiques
- même angle avec seul changement de wording
- messages génériques “économisez”, “découvrez”, “profitez” sans douleur précise
- LP qui raconte une autre histoire que l’ad

## Checklist d’audit express
1. Les ads sont-elles taguées par angle / format / awareness ?
2. Les winners sont-ils analysés ou juste remplacés ?
3. Le compte est-il trop BOF ?
4. La first frame fait-elle le ciblage ?
5. La LP répète-t-elle la promesse et le persona de l’ad ?
6. Le batch contient-il de vraies différences conceptuelles ?
7. Les commentaires / reviews ont-ils nourri les hooks ?
8. Les décisions de kill / keep sont-elles définies à l’avance ?

## Sortie attendue en analyse
Toujours relier les recommandations à un signal observable :
- concentration de spend
- faible diversité réelle
- mismatch ad/LP
- surreprésentation BOF
- absence de documentation angle/hook/format
- failure à exploiter un winner

## Ton de restitution pour Erwan
- Répondre de façon naturelle, directe, conversationnelle.
- Éviter les sections rigides de type « Diagnostic / Hypothèse / Priorité / Test / KPI / Risques » si l'utilisateur demande simplement un avis ou une reco.
- Commencer par l'avis franc, puis expliquer avec les signaux concrets.
- Préférer « je pense que / ce que je vois / donc je ferais » à un format de rapport figé.
- Quand il demande une décision simple (« on coupe quoi ? », « on itère sur quoi ? »), répondre d'abord avec l'action recommandée, puis la justification courte.
- Quand il dit explicitement qu'il ne veut pas de "suggestions" mais une direction d'expert, ne pas proposer plusieurs options ni renvoyer la décision au user. Trancher, donner un plan unique, puis expliquer brièvement pourquoi c'est le bon move.

## Formule de travail
**Même message central, plusieurs angles distincts, plusieurs formats, même histoire sur la LP, puis itération depuis les gagnants.**
