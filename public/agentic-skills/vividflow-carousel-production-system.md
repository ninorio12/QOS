# VividFlow Carousel Production System

## Core Principle

A VividFlow carousel is a sequence of visual scenes that converts an operational pain into a need for a system. It is not a slide deck, not a document, and not generic AI education.

## Mandatory Creative Formula

Every carousel must have:

1. One concrete operational problem.
2. One sharp contradiction.
3. One word pivot per key slide.
4. One visual proof per slide.
5. Stable VividFlow brand components.
6. A conversion CTA.

## Default Narrative Arc

1. **Truth shock**
   - Name the painful reality.
   - Use a short phrase that could stand alone.

2. **False problem**
   - Show what the agency leader thinks the problem is.

3. **Real problem**
   - Reframe the issue operationally.

4. **Cost**
   - Show what it burns: mandate, time, focus, response speed, reporting trust.
   - Do not invent numbers.

5. **VividFlow mechanism**
   - Show the agentic operating layer: capture, route, qualify, relance, alert, report.

6. **CTA**
   - Demo, audit, diagnostic, benchmark, or current destination.

## Slide Construction Rule

Each slide needs:
- Headline: one idea, 5 to 14 words if possible.
- Word pivot: capsule, selection, black bar, sticker, strike-through, or glow object.
- Visual proof: UI, object, human scene, workflow line, notification, dashboard, CRM card.
- Background emotion: orange/action or blue-black/control.
- Brand pill bottom-left when carousel format applies.
- Chevron or CTA bottom-right.

## Copy Pattern Library

Use these structures:

- “Le problème n’est pas [faux problème]. C’est [vrai problème].”
- “Vous ne manquez pas de [surface]. Vous manquez de [système].”
- “Quand [situation], [conséquence].”
- “[Mot fort] bat [ancien réflexe].”
- “[Ancien outil] ne suffit plus quand [enjeu opérationnel].”
- “Ce qui n’est pas [mesuré / routé / suivi] finit par [se perdre / coûter / ralentir].”

Avoid:
- Broad AI evangelism.
- Feel-good founder content.
- Generic market commentary.
- Invented proof.
- Human public figure signature.

## Calibration Mode

When Jonathan asks to “generate a new post” to get closer to the reference examples, stay in calibration mode:
- Do not try to move to a “higher stage” or invent a new direction.
- Optimize for resemblance to the provided VividFlow examples first: aphorism, contradiction, word pivot, scene, brand pill, swipe rhythm.
- Deliver a visible draft quickly enough to judge direction, but label it as calibration draft, not final prod.
- Iterate one asset at a time until the reference level is reached.
- After each visual QA or Jonathan correction, patch the relevant skill before creating the next draft.
- If Jonathan says the direction is right but the result is not detailed/realistic enough, keep the same strategic angle and improve execution fidelity instead of changing concept.
- If a hero device/object looks fake and no realistic asset generation is available, pivot to a high-detail product interface scene or single-slide format test.
- If Jonathan asks to “show what you can do with what you have”, stop asset hunting, produce a small visible calibration draft immediately, QA it, and label it honestly as potential/calibration.
- Use single-slide “format scout” tests when visual fidelity is the bottleneck; scale to multi-slide only after the style feels close to the references.
- Before Jonathan sees any new calibration draft, load and apply `vividflow-typography-calibration` and `vividflow-realistic-scene-design`.

## Quality Gate

Reject before delivery if:
- It would work for any generic AI SaaS.
- There is no operational real-estate pain.
- The word pivot is not visually dominant.
- The slide feels like a static report.
- There is no VividFlow mechanism.
- The CTA is missing or weak.
- More than one main idea competes on the slide.
- Any collision remains between title, body text, UI cards, brand pill, chevron, or CTA card.
- The draft is described as final while still needing Figma-level micro-corrections.
- It reverts to fake CSS devices or generic web typography after Jonathan already rejected that class of output.
- It restarts a new concept instead of improving the specific failure class Jonathan just named.

## Common Mistakes

- Overbuilding UI cards instead of making one idea memorable.
- Using orange only as decoration.
- Making a “nice” carousel with no conversion mechanism.
- Repeating the same layout across all slides.
- Treating the brand pill as optional.
- Writing copy before choosing the visual metaphor.
- Leaving HTML/screenshot layout collisions because the asset is “only a draft”. Drafts still need collision QA before Jonathan sees them.
