# VividFlow Realistic Scene Design

## Core Principle

VividFlow visuals must feel like a believable operational scene, not a fake device mockup or decorative SaaS dashboard.

## Scene Composition

Prefer one of these formats:
- Real-estate desk scene: mandate folder, keys, property sheet, laptop/CRM glow.
- Product intelligence scene: detailed cockpit UI, CRM card, alert, timeline, assignment, owner risk.
- Human-operational scene: agent overloaded, owner follow-up, messages and CRM signals around them.

## Detail Density Rules

Every UI scene needs functional micro-details:
- Lead type, source, status, owner/client context.
- Assignment, delay, risk, next action.
- Timeline or workflow that explains the mechanism.
- One alert or signal that proves VividFlow catches what humans miss.

## Realism Rules

- Do not hero fake CSS phones or laptops.
- If no real asset exists, build a product scene instead of fake hardware.
- When using image generators such as Higgsfield, generate the mature scene/background first and keep final headline/body/brand typography for a controlled design layer.
- Avoid asking the image model to render small readable text inside documents, dashboards, phones, or notes. Prefer abstract/blurred forms or leave space for real labels added later.
- UI labels must sound like a real Swiss real-estate agency workflow.
- Objects must support the message: keys, mandate, estimation, property, owner, visit, CRM.
- Glows, grids and blur are depth layers, not the concept.

## UI Credibility Checklist

- Would a real agency understand the screen?
- Does every card have a purpose?
- Are micro-labels readable enough?
- Are shadows, radius, borders and spacing consistent?
- Does the main alert avoid covering important information?

## Reject If

- The visual would work unchanged for any B2B SaaS.
- Device/object realism is lower than the reference posts.
- UI data is vague placeholder copy.
- Decorative cards outnumber meaningful operational signals.
- The scene does not contain real-estate context.
