# VividFlow Content Production

## Current Strategic Direction

VividFlow is now a generalist B2B premium AI agents / automation infrastructure studio, not an immobilier-only offer. Content may still use real estate as a case study, but default positioning must be sector-agnostic: TPE/PME, larger accounts, institutions, and any organization with operations to automate.

## Core Principle

VividFlow content is not “a nice post”. It is a conversion and authority asset for business leaders who need clearer operations, faster execution, and practical AI agents. Never jump from an idea directly to a finished carousel. Build the strategic spine first, then the visual system.

Strategic correction: VividFlow is no longer immobilier-only. Use real estate only for explicit client/use-case contexts. Current direction is generalist B2B, with insurance also validated by signed client context.

## Mandatory Workflow

1. **Choose one operational pain**
   - Manual lead or request handling
   - Follow-up chaos across WhatsApp/email/CRM/tools
   - Support tickets and repetitive customer questions
   - Admin/back-office document processing
   - Reporting and data consolidation
   - Team coordination and handoffs
   - Content production and distribution
   - Sector-specific friction only when the asset is a vertical case study
   - Sector-specific pain only when the campaign is verticalized

2. **Write the conversion spine**
   - Problem: concrete daily pain
   - Cost: lost time, missed revenue, slower execution, client frustration, team drift
   - VividFlow solution: agents IA + automation + operational systems
   - Proof: only if verified
   - CTA: audit, call, demo, or diagnostic as currently available

3. **Pick the creative format**
   - Conceptual: one message, one symbol, one emotion
   - Narrative: human/context/situation
   - Educational: framework, steps, UI explanation
   - Analytical: belief reversal, reasoning, lesson
   - Sequenced: problem → explanation → action

4. **Produce the slide script before visuals**
   - One idea per slide
   - Hook understood in under 2 seconds
   - Maximum 3 supporting points per slide
   - No generic AI claims
   - No invented numbers or fake case studies
   - For prospecting/deck slides, hide backend concepts if they create friction. “Mémoire”, “source de vérité” and architecture terms can be true internally but should not be the visible message unless the user explicitly wants product education.
   - Prefer human-operational phrasing: “Les agents préparent. Vos consultants gardent la relation.” Show agents relieving repetitive work before explaining the infrastructure.

5. **Apply DA with precision**
   - Font: Poppins Medium when available
   - Palette: #FA5001 orange, #080807 black, #E0E0E0 grey, white
   - Keywords: premium, confiance, élégance sobre, clarté, modernité, sécurité, Suisse
   - Effects: orange accents, dark premium base, glass/UI cards only when they serve the message

6. **Quality gate before delivery**
   - Does it beat a basic designer output?
   - Is the message specific to a real operational pain, not generic AI hype?
   - Does every visual element carry meaning?
   - Is there a clear funnel role: TOFU, MOFU, BOFU?
   - Are there any layout collisions, tiny text, weak hierarchy, placeholders, or generic SaaS visuals?

## Website / Landing Page Copy Rules

Use these when producing VividFlow site sections, landing pages, hero copy, FAQ, agent/service cards, or short profile bios derived from the site positioning.

### Short bios / profile copy

- Preserve the validated strategic base instead of generating a new hook every reply. If Jonathan likes “IA opérationnelle pour entreprises”, keep it as the anchor and only iterate the line underneath.
- Start from the ICP’s felt problem and desired outcome, not from a feature inventory. The ICP often does not know what AI agents can take over yet; avoid framing the public promise as “we help you identify”. Identification is an internal step, not the offer.
- Prefer clear operational benefit over clever wording: time saved, less manual work, faster execution, more operational capacity.
- Include “agents IA” only as the mechanism under the broader category “IA opérationnelle”, not as the whole positioning when the scope is wider.
- When Jonathan asks for a shareable message or simple public copy, return a clean block he can paste directly. Avoid status tables, internal diagnostics, or long rationale unless asked.

- Work step-by-step: always state the last validated step and the next step. If a section is not validated, keep brainstorming instead of moving forward.
- Be a coordinator, not a mirror: take a position based on the validated VividFlow vision, challenge weak ideas, and avoid validating by comfort.
- Keep one clear voice. Do not speak as “all agents” or imply multiple agents are jointly replying unless the user explicitly requests group coordination.
- Public positioning is generalist B2B premium: AI agents and operational infrastructure for any organization, from TPE/PME to large accounts and institutions. Do not narrow to real estate except for a specific case study.
- Surface language must be simple for non-technical leaders; hidden depth can be infrastructure, orchestration, memory, workflows, and integrations.
- For hero copy, prefer market statements over corporate phrasing. Avoid “VividFlow fait…”. Prefer formulations like “L’IA opérationnelle…” and subtitles with “Nous déployons…” or “VividFlow délivre…” only when useful.
- For CTAs, use “Réserver un appel” where needed, but avoid sounding desperate or salesy. The final block can be visionary/simple rather than another hard sell.
- FAQ answers should match the Naiom-style shape: short, direct, reassuring, one main idea, simple words, benefit-oriented, not technical/legalistic.
- Agent cards should feel like agents doing real work, not feature checklists: use a human name, role, short description, then concrete “Ce qu’il/elle peut faire” bullets. Bullets should be immersive action phrases without final punctuation.
- Agent names can be multicultural and meaningful. Validated VividFlow agent names: Amani, Mei, Akira, Nia, Sora, Imani, Kenzo, Aya, Mino. Mino is the execution agent, named after Minozan, Jonathan’s partner/brother who introduced him to AI.

## Slide / Deck Clarity Rules

When a slide explains agents or operational flow, favor concrete activity over backend concepts. If Jonathan flags “mémoire” or similar system language as unclear, hide it as backend and show the visible outcome instead: sources → agents IA working → actions/notifications → human decision. Avoid titles that feel like rigid blocks; use breathable hierarchy. For agent slides, make agents feel active with subtle motion, varied agents, and small counters/notifications such as “+4 échanges résumés”, “+3 dossiers préparés”, “+6 relances proposées”, “+2 actions prêtes à valider”. Keep only 3–4 notifications visible and avoid dashboard/KPI heaviness.

## Hard Rules

- Never publish or present a graphic as final if it is only a technical mockup.
- Do not rely on black/orange/glassmorphism as the full design idea.
- Do not create fake dashboards with fake metrics unless clearly marked as illustrative.
- Do not use Jonathan or Thomas as public figures for VividFlow unless explicitly approved for founder/content strategy.
- Do not mention Brvndlab, Kalvi, Hermes, or internal agent status.
- Do not use em-dashes.
- Use formal French: always “vous” for the market.
- Do not frame VividFlow as immobilier-only unless the request is explicitly about a real estate vertical page/case.

## Failure Pattern to Avoid

A previous test carousel was readable but not strong enough. It applied the surface DA but lacked the design sophistication and calibrated model required to replace the former graphic designer. Future outputs must separate strategy, copy, DA, and execution instead of rushing to a rendered artifact.

## Minimum Deliverable for a New Carousel Request

Before producing visuals, return:
- Problem chosen
- Funnel stage
- Creative format
- Slide-by-slide script
- Visual direction
- CTA

Only produce final graphics after the script and direction are accepted or after Jonathan explicitly asks for a rough test.

## Prospection / Discovery Deck Iteration

When Jonathan iterates VividFlow prospection deck slides, use `references/prospection-deck-slide-patterns-2026-06.md` for validated slide 5 and slide 7 patterns.

Rules from calibration:
- If Jonathan says “trop d’info”, “ça fait mal aux yeux”, or struggles to identify the message, reduce to one human benefit plus one visual mechanism.
- Do not foreground internal abstractions like “mémoire cabinet” if the prospect needs to feel agents working and consultants being relieved.
- Agent visuals should feel active but calm: avatars + iPhone/WhatsApp-style notifications beat abstract counters or dashboards.
- Avoid repeating the same idea in the title and side card; every copy block must add a distinct role.
- When Jonathan asks for “prompt”, provide a paste-ready implementation brief directly.
