Donc oui : **même bot Dev**, mais il travaille comme plusieurs devs spécialisés par module.

## Pourquoi c’est mieux

Parce qu’un SaaS se casse souvent quand plusieurs agents touchent :
- les mêmes composants
- les mêmes routes
- le même schéma DB
- les mêmes layouts
- les mêmes providers

Avec un découpage par module :
- moins de conflits
- contexte plus clair
- meilleure qualité
- previews séparées
- tu peux valider module par module

## Règle simple

```text
Un worker ne touche que son module.
```

Exemple :

### Worker Brand OS
Autorisé :
```text
/app/brand-os/**
/components/brand-os/**
/convex/brandOs*
```

Interdit sauf validation COO :
```text
/app/dashboard/**
/app/settings/**
/components/shared/**
/convex/schema.ts
```

### Worker Content
Autorisé :
```text
/app/content/**
/components/content/**
/convex/content*
```

Interdit sauf validation :
```text
/app/brand-os/**
/app/dashboard/**
/components/shared/**
```

```text

```

Si un module doit toucher ça, il doit le signaler :

```text

```
