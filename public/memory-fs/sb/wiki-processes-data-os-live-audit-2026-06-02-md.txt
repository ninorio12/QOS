## Lecture COO

Le Data OS a déjà la bonne structure de navigation pour devenir source de vérité. Le point clé n’est pas d’ajouter des modules, mais de connecter les flux agents aux modules existants.

## Mapping Slack vers Data OS

- cmo-visuel → Records / Projets / Base de connaissance / Tâches
- service-client → Leads / Clients / Conversations / Tâches
- data-analyst → Data / Analyse / Records
- ops-systeme → Process / Tâches / Activités
- COO → validation, routage, synthèse, audit log

## Premier workflow à brancher

Slack message validé par COO → Data OS Inbox/Record → Task ou Decision → Agent run → Activity log → GBrain note si durable.

## Manques à vérifier ensuite

- Existe-t-il une API ou base Convex accessible pour créer records/tasks ?
- Les objets Agent run / Activity log sont-ils réels ou seulement UI ?
- Les actions sensibles ont-elles un état approval ?
- Chaque record expose-t-il source, auteur, canal, timestamp, statut validation ?
