# Context Relevance Gate — Anti-pollution GBrain

Objectif: empêcher un résultat de recherche Second Brain de hijacker une réponse opérationnelle.

## Protocole obligatoire
1. Identifier la demande active de Jonathan.
2. Classer les résultats récupérés: source officielle, état live, décision durable, archive, raw, live-event, signal automatique.
3. Utiliser seulement les résultats qui passent les 4 filtres:
   - même sujet/intention;
   - même entité explicitement nommée;
   - même temporalité utile;
   - même type d'action attendue.
4. Si un résultat est archivé, raw, live-event ou signal automatique: il est low-trust par défaut.
5. Si l'entité n'est pas nommée par Jonathan, ne pas l'introduire.
6. Si le résultat est parasite: l'ignorer silencieusement.

## Exemple bloquant
Demande: chercher/comprendre une règle email.
Résultat GBrain: ancien contrat Bula/Raphaël.
Décision: ignorer. Ne pas mentionner Bula. Ne pas proposer contrat. Ne pas afficher le résultat.

## Sources de vérité
- Data OS: état vivant/tâches/clients/owners.
- Second Brain: décisions/process/concepts validés.
- GBrain: moteur de recherche seulement.
- raw/live-events/signaux automatiques: fallback ciblé uniquement.
