## Compte rendu — Call “Implémentation / onboarding / délivrabilité agents IA”

**Durée :** 146 min 
**Sujet central :** comment onboarder un client, auditer son business, livrer une infrastructure IA/Hermès, puis upsell vers un système multi-agents.

## 1. Idée principale

Le call détaille le process d’agence pour vendre et livrer des agents IA.

La logique est :

1. **R1 découverte / endoctrinement**
 - Éduquer le prospect sur ce que l’IA peut réellement faire.
 - Lui faire comprendre que son business peut être transformé par une couche agentique.
 - Utiliser un deck visuel, simple, orienté douleur → solution → vision.

2. **R2 proposition**
 - Présenter un hub personnalisé :
 - cahier des charges,
 - maquette,
 - simulateur ROI,
 - vision de l’agent livré.

3. **Onboarding**
 - Formulaire client complet.
 - Récupération des accès, process, SOPs, outils, documents métier.
 - Drive partagé pour nourrir la base de connaissance.

4. **Audit 2h**
 - Étape la plus importante.
 - Cartographier tous les process internes.
 - Chiffrer le ROI de chaque automatisation.
 - Prioriser les 3 premiers agents à livrer.

5. **Livraison**
 - Client crée son VPS.
 - L’agence déploie Hermès / second cerveau / contexte / structure client.
 - Connexion aux outils métier.
 - Puis livraison agent par agent.

6. **Upsell**
 - Agent “bras droit” initial à ~5k€.
 - Puis upsell vers agents spécialisés à 15k–20k€.
 - Rétention via DFY, DWY ou recrutement/formations internes.

## 2. Modèle économique expliqué

Le produit d’appel est un **agent bras droit à 5k€**.

Mais ce n’est pas censé être le vrai centre de profit. Il sert surtout à :

- faire entrer le client,
- prouver la valeur,
- créer la confiance,
- auditer en profondeur,
- identifier les départements à automatiser.

Ensuite, l’argent est dans les upsells :

- Agent Sales
- Agent Marketing
- Agent RH
- Agent Finance
- Agent Ops
- Agent Support
- etc.

Chaque agent spécialisé peut être vendu entre **15k€ et 20k€** selon complexité / impact business.

Point important : ils acceptent une marge plus faible sur le premier agent si ça permet de verrouiller le client et de créer le terrain pour les gros upsells.

## 3. Audit : le cœur du système

L’audit de 2h est présenté comme l’étape critique.

Objectifs :

- Comprendre le business en détail.
- Cartographier les process métier.
- Identifier les tâches répétitives / lentes / coûteuses.
- Chiffrer le temps perdu.
- Calculer le ROI d’automatisation.
- Prioriser les agents à construire.

Exemple donné :

Si un CEO perd 4h/semaine sur une tâche et vaut 1500€/h, ça représente :

- 4h x 1500€ = 6000€/semaine de valeur récupérable.

Donc l’agent n’est pas vendu comme un gadget technique, mais comme une récupération de valeur économique.

Critères de priorisation des agents :

1. Facilité d’implémentation.
2. Impact direct sur le revenu.
3. Gain d’efficacité opérationnelle.

## 4. Livraison technique

Le client possède son infrastructure.

Process :

- Le client crée son VPS, typiquement Hostinger KVM2.
- L’agence déploie l’infra dessus.
- Hermès sert d’agent central.
- Une commande de type `/client_implementation [client_name]` permettrait de déployer :
 - second cerveau,
 - contexte client,
 - structure,
 - base de connaissance,
 - connexions nécessaires.

L’idée importante : l’agence garde un **DataOS interne** qui contient le contexte client et permet de répliquer/déployer rapidement les infrastructures.

Temps annoncé : **20–30 minutes** pour déployer une base client si le process est bien standardisé.

## 5. Architecture agentique

Ils distinguent :

- **Agent orchestrateur**
 - Centralise.
 - Coordonne.
 - Peut avoir des skills.
 - Sert de bras droit.

- **Agents spécialisés**
 - Sales.
 - Marketing.
 - RH.
 - Ops.
 - Finance.
 - etc.

Pourquoi segmenter ?

- Meilleure spécialisation.
- Meilleur cloisonnement des données.
- Un agent marketing n’a pas besoin d’accéder aux données financières.
- Ça rend aussi l’upsell plus naturel : chaque département devient une opportunité commerciale.

Point important : l’orchestrateur seul a une limite. Sa vraie valeur augmente quand il a des “employés”, donc des agents spécialisés autour de lui.

## 6. Connexion aux outils

Ils privilégient :

1. **API-first**
 - CRM,
 - cloud,
 - Meta Ads,
 - Google,
 - Convex,
 - Vercel,
 - etc.

2. **Invitations par email**
 - Plutôt que demander les mots de passe.

3. **Browser automation quand pas d’API**
 - Mention de Browser Use / Browserless / Browser Harness.
 - L’agent peut apprendre à manipuler une interface web comme un humain.
 - Utile pour outils legacy ou SaaS sans API exploitable.

Ce point est très pertinent pour nous : ça confirme que la couche navigateur/CDP est stratégique pour traiter les outils non intégrables proprement.

## 7. Sécurité / souveraineté des données

Objection principale : “Où vont mes données ?”

Réponse proposée :

- Le client possède son VPS.
- Les données restent sur son infrastructure.
- L’agence peut avoir un accès monitoring/optimisation uniquement avec accord.
- Traitement externe principal : API OpenAI.
- Positionnement : OpenAI est soumis à des exigences fortes, notamment européennes, donc peut être défendu côté sécurité.

Pour données sensibles :

- Option monitoring uniquement.
- Option anonymisation.
- Option limitation d’accès par agent.
- Human-in-the-loop pour actions irréversibles.

Point contractuel :

- Si le client utilise mal son agent, la responsabilité doit être transférée contractuellement au client.
- Les actions sensibles doivent avoir des garde-fous.

## 8. Rétention

Trois modèles récurrents :

### DFY — Done For You
L’agence garde un développeur / opérateur IA à temps partiel pour maintenir et améliorer l’infra.

### DWY — Done With You
Coaching / consulting mensuel. Exemple évoqué : autour de 1k€/mois pour plusieurs sessions.

### DIY
L’agence aide le client à recruter et former un développeur interne pour qu’il devienne autonome.

Le récurrent n’est pas forcément vendu comme maintenance technique pure, mais comme :
- optimisation continue,
- nouveaux agents,
- supervision,
- conseil,
- montée en compétence.
