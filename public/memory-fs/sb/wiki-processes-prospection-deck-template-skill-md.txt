# Prospection deck — template strict à trous

## Décision

Les pages de prospection personnalisées VividFlow ne doivent pas être traitées comme une inspiration libre. Elles doivent être remplies comme un **template strict à trous**, en reprenant la structure validée de références comme CC Concept et Schmid Signature, sans toucher au design ni à la séquence.

## Entrée attendue

Claude reçoit principalement un nom de domaine d’entreprise. Il doit :
- rechercher l’entreprise sur internet ;
- identifier le CEO ou décisionnaire probable ;
- indiquer le niveau de confiance sur l’identité trouvée ;
- comprendre l’activité, les frictions opérationnelles visibles et l’angle VividFlow pertinent ;
- inclure le décisionnaire dans les simulations de conversation quand le template le demande.

## Notice page par page

Pour Thomas ou Claude, chaque page doit être décrite avec :
1. rôle de la page ;
2. émotion à créer ;
3. message exact à faire passer ;
4. copy attendue : titre, sous-texte, mots interdits ;
5. visuel : composition, style, objets/scène/métaphore ;
6. transition narrative avec les pages autour ;
7. logique reprise du dossier Outreach ou de la référence validée ;
8. adaptation propre au prospect.

## Garde-fous

- Ne pas inventer une structure de deck.
- Ne pas modifier le design.
- Ne pas ajouter d’audit complet ou de promesse générique.
- Ne pas reformuler en copy plaquette ou fiche entreprise.
- Éviter les angles mous type “gain de temps” si le contexte permet une friction plus concrète.
- VividFlow doit rester positionné comme installation d’agents IA opérationnels / continuité d’exécution, pas chatbot ou CRM basique.

## Simulation conversation page 7 — correction validée — 2026-06-15
Sources : `raw/messages/20260615-173412_telegram-session_30a58543.md`, `raw/messages/20260615-173412_telegram-session_9e465a33.md`, `raw/messages/20260615-173412_telegram-session_243c66bc.md`.

Correction validée : la page 7 / simulation ne doit pas commencer par un message de prospect/patron artificiel et descriptif. Le premier message doit être une phrase humaine courte adressée au bras droit IA, avec une demande d’action concrète.

Pattern obligatoire : **message humain simple → IA retrouve le contexte → actions préparées → validation humaine**.

Interdits : long tiret `—`, phrase trop écrite par IA, détails complets dès le premier message, scène qui ne demande pas explicitement au système d’agir.

Exemple de logique correcte : “On a une relance d’acquéreurs sur une offre en cours. Tu peux préparer le suivi ?”

Point d’exécution : ne pas confondre deck outbound de projection email avec une page R2 / solution. Pour un test outbound type JPF, livrer le deck de projection email au format référence CC Concept / Schmid Signature / Kids Care, avec URL exploitable après build/déploiement et vérification.
