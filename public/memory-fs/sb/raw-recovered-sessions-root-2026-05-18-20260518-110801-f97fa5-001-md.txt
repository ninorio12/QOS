## Le vrai risque

Le risque n’est pas “malware classique”. 
Le risque est **data/privacy + supply chain + mutation incontrôlée**.

### 1. Lecture de données sensibles
Le mode `--eval-source sessiondb` lit :
- `~/.claude/history.jsonl`
- `~/.copilot/session-state/*/events.jsonl`
- `~/.hermes/sessions/*.json`

Donc il peut envoyer des bouts d’historique de conversations à un LLM via DSPy/OpenAI/OpenRouter.

Il y a bien un filtre anti-secrets, mais il est incomplet par nature. Il peut rater :
- infos clients,
- contexte business sensible,
- décisions internes,
- liens privés,
- tokens non standards,
- données perso.

### 2. Dépendances non pinées
`pyproject.toml` utilise :
- `dspy>=3.0.0`
- `openai>=1.0.0`
- `pyyaml>=6.0`
- `click>=8.0`
- `rich>=13.0`

Pas de lockfile. Donc l’installation peut tirer des versions futures non contrôlées.

### 3. Le garde-fou “tests” est optionnel
Dans le README, ils disent full test suite obligatoire. 
Dans le code, `--run-tests` est un flag, pas activé par défaut. Et dans le flow actuel, la validation principale reste surtout :
- taille,
- structure,
- non-empty,
- croissance max.

Donc les guardrails annoncés sont plus forts que l’implémentation réelle.

### 4. Ça peut produire de mauvais skills “convaincants”
Le scoring est assez faible : overlap de mots-clés / LLM-as-judge. 
Donc il peut générer un skill qui “score mieux” mais dérive du vrai comportement attendu.

## Verdict

Je ne partirais pas direct sur un gros repo type PowerPoint clone.

**Meilleure approche : build un mini-editor interne VividFlow**, focalisé sur nos douleurs réelles :

- déplacer une caption
- aligner des sections
- bouger CTA / logo / cartes
- resize textes / cards / screenshots
- sauvegarder en JSON
- exporter PNG/PDF

## Pourquoi

Notre problème n’est pas “faire PowerPoint en ligne”. 
C’est : **arrêter de perdre du temps sur des micro-ajustements visuels que l’agent devine mal en statique.**

Donc il faut une fonction editor avec :

- canvas central
- éléments sélectionnables
- drag & drop
- resize
- inspector X/Y/W/H
- align left/center/right
- grid / safe margins
- export image
- sauvegarde positions JSON

## Repos intéressants trouvés

- `pipipi-pikachu/PPTist` 
 Full PowerPoint-like editor. Puissant, mais lourd, Vue/TS, probablement overkill.

- `slidevjs/slidev` 
 Très bon pour decks Markdown dev, mais pas idéal pour déplacer visuellement une caption.

- `tldraw` / canvas primitives 
 Bon si on veut un canvas interactif, mais il faut construire la logique deck/export autour.

## Ma reco

**Build custom léger en React** :

- `react-konva` ou `fabric.js`
- `zustand`
- schema JSON d’éléments
- export PNG
- format presets : 16:9, 4:5, 1:1, 9:16
- mode deck avec slides à gauche, canvas au centre, inspector à droite

C’est plus rapide et plus adapté à VividFlow qu’un clone PowerPoint.
