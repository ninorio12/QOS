SECTION 5/6 : le Rail Contextuel
Le rail contextuel est la 3e zone à droite de l'écran. Il s'ouvre uniquement quand un objet métier est en cours d'inspection dans le main canvas. Il porte les 4 transverses (Tâches, Décisions, Risques, Historique) appliquées spécifiquement à cet objet ouvert.

Quand le rail s'ouvre, quand il se ferme
Tu navigues dans Pipeline (vue liste) → rail fermé. Main canvas plein écran.
Tu cliques sur un prospect dans la liste → fiche prospect s'ouvre dans le main canvas + rail s'ouvre automatiquement à droite.
Tu fermes la fiche (✕ ou retour liste) → rail se referme.
Tu cliques sur un autre prospect → la fiche change ET le rail recharge son contenu pour le nouveau prospect.
C'est automatique. Pas de bouton manuel pour ouvrir/fermer. La présence du rail signale "tu es en train de travailler sur UN objet précis".

Structure du rail

┌────────────────────────────────┐
│ [icône] Nom de l'objet [×] │ ← header sticky
│ Type · Owner · Statut │ (méta de l'objet ouvert)
├────────────────────────────────┤
│ ▼ Tâches (3) │
│ ☐ Tâche 1 │ ← cochable directement
│ ☐ Tâche 2 │
│ ☐ Tâche 3 │
│ + Ajouter une tâche │
├────────────────────────────────┤
│ ▼ Décisions (1) │
│ ◆ Décision en attente │
│ • Contexte, options │
│ [Trancher] [Reporter] │
├────────────────────────────────┤
│ ▶ Risques (1) │ ← collapsed par défaut
├────────────────────────────────┤
│ ▶ Historique │ ← collapsed par défaut
└────────────────────────────────┘
Largeur fixe ~400px. Pas de resize en v1.

Header du rail (sticky)
Icône + nom de l'objet (ex. Mathieu Durand · Prospect · En qualification · Owner JZ).
Bouton ✕ pour refermer (équivalent au retour liste).
Pas de menu contextuel ici. Les actions sur l'objet (modifier, archiver, etc.) sont dans le main canvas, pas dans le rail.
Bloc Tâches (ouvert par défaut)
Liste des tâches liées à cet objet uniquement.
Compteur dans le titre : Tâches (3).
Chaque tâche : checkbox + libellé + échéance + owner.
Action en ligne : cocher = marquer faite.
Bouton "+ Ajouter une tâche" en bas du bloc.
Si aucune tâche : "Aucune tâche sur ce prospect" + bouton ajouter.
Bloc Décisions (ouvert par défaut)
Liste des décisions en attente sur cet objet.
Chaque décision : intitulé + contexte court + 2 boutons rapides (Trancher / Reporter).

Bloc Risques (collapsed par défaut)
Liste des risques actifs sur cet objet.
Chaque risque : type + sévérité (couleur subtile) + signal détecté + suggestion d'action.

Collapsed par défaut car le risque est une zone de vigilance, pas une zone d'action quotidienne. Si présent, badge subtil sur le titre du bloc.

Timeline reverse-chronologique de tout ce qui s'est passé sur cet objet.
Chaque événement : timestamp + acteur (humain ou agent, avec badge "fait par agent X") + action.

Rail vs Drawer Notifications : la séparation explicite
Tu avais flagué le risque de confusion en validation du Header. Voici la règle claire :

Rail contextuel Drawer notifications
Position Zone droite Zone droite
Trigger Ouverture d'un objet métier Clic sur la cloche du header
Périmètre UN objet précis Toute l'app, tous objets
Contenu Tâches/Décisions/Risques/Historique de CET objet Inbox opérationnelle globale
