Concrètement, ce trio nous donne une **chaîne UX SaaS complète** dans Hermes :

## 1. `frontend-design`
**Rôle : produire des interfaces SaaS qui ne ressemblent pas à du template IA.**

Ça sert quand on veut :
- créer une page SaaS premium
- refaire un dashboard
- améliorer une sidebar / navbar / card / onboarding
- sortir une UI plus “Linear / Vercel / Stripe” mais adaptée au produit
- éviter les layouts génériques : fond blanc, cards rondes, gradient violet, Inter partout

**Exemples d’usage :**
- “Refais le dashboard Brvndlab avec une DA plus premium”
- “Crée une page analytics SaaS pour coachs”
- “Rends ce module plus clean et plus produit B2B”
- “Propose 3 directions UI pour ce CRM agentique”

Résultat attendu : **code frontend ou specs visuelles plus haut niveau**.

---

## 2. `design-consultation`
**Rôle : créer ou clarifier un vrai système de design.**

Ça sert quand on veut :
- définir une direction visuelle globale
- créer un `DESIGN.md`
- cadrer couleurs, typo, spacing, composants, motion
- éviter que chaque écran ait un style différent
- transformer “on veut un SaaS premium” en règles concrètes réutilisables

**Exemples d’usage :**
- “Crée le design system VividFlow”
- “Analyse l’app et formalise un DESIGN.md”
- “On veut une DA plus agentic OS, pas chatbot”
- “Définis les règles UI pour Brvndlab v2”

Résultat attendu : **source de vérité design** qu’un agent peut charger avant de coder.

Point de vigilance : ce skill peut proposer d’écrire dans `CLAUDE.md` / fichiers projet. On le garde sous contrôle.

---

## 3. `adversarial-ux-test`
**Rôle : tester le SaaS comme un utilisateur difficile, pas comme un dev.**

Ça sert quand on veut :
- trouver les frictions réelles
- voir où un utilisateur abandonne
- tester onboarding, pricing, signup, empty states
- détecter le jargon trop interne
- repérer les écrans “techniquement OK mais humainement flous”

**Exemples d’usage :**
- “Teste Brvndlab comme un coach de 45 ans pas très tech”
- “Fais un audit UX de l’onboarding”
- “Trouve pourquoi un utilisateur ne comprend pas le Brand OS”
- “Teste la landing comme un prospect froid”

Résultat attendu : **liste de problèmes UX priorisés**, avec actions concrètes.
