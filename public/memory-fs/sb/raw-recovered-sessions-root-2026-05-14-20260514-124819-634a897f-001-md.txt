# DESIGN.md — VividFlow

## 1. Positionnement visuel

VividFlow doit ressembler à une infrastructure SaaS premium pour agences immobilières suisses.

Le produit ne doit jamais donner l’impression d’un chatbot, d’une agence marketing, ni d’un template IA générique. L’interface doit communiquer : contrôle, précision, confidentialité, fiabilité opérationnelle.

Mots-clés : sobre, premium, Swiss B2B, conversation-first CRM, agentic operating layer, immobilier, pipeline, suivi, mandats, décisions.

À refuser : neon AI, glassmorphism gratuit, dashboards remplis de chiffres vides, mascottes, hype futuriste, interface trop “startup US”, effet outil bricolé.

## 2. Tokens de marque

### Couleurs

- Noir primaire : `#080807`
- Orange VividFlow : `#FA5001`
- Gris clair : `#E0E0E0`
- Fond app clair : `#F7F5F2`
- Surface blanche : `#FFFFFF`
- Surface sombre : `#11100F`
- Texte principal : `#141312`
- Texte secondaire : `#6F6B66`
- Bordure subtile : `#E7E2DC`
- Succès : `#2F8F5B`
- Warning : `#C9822B`
- Danger : `#C44536`

Usage : l’orange ne sert pas à décorer. Il signale une action, une priorité, une transition, un risque ou une opportunité commerciale.

### Typographie

- Primaire : Poppins Medium / Semibold
- Fallback : Inter ou system sans-serif uniquement si nécessaire
- Titres : compact, précis, forte hiérarchie
- Body : lisible, jamais trop petit
- Chiffres / statuts : tabular, nets, orientés décision

### Spacing

- Base : 4px
- Compact : 8 / 12 / 16
- Standard : 20 / 24 / 32
- Sections : 40 / 56 / 72

Règle : espace généreux sur les écrans exécutifs, densité contrôlée sur inbox/pipeline.

### Radius

- Small : 8px
- Medium : 12px
- Large : 18px
- Panels principaux : 20-24px

Éviter le tout-arrondi “SaaS cute”. Les formes doivent rester nettes.

### Ombres / profondeur

- Ombres très sobres, jamais “floating cards” gratuites.
- Préférer bordure + surface + contraste plutôt que blur excessif.
- Les overlays doivent donner une sensation d’outil sérieux, pas de landing page crypto.

## 3. Architecture UI SaaS

### App shell

- Sidebar gauche stable, sobre, orientée modules métier.
- Top bar utile : workspace, recherche, statut agents, notifications, profil.
- Zone centrale : priorité au workflow actif, pas aux widgets décoratifs.

Modules à prévoir : Conversations, Contacts, Pipeline, Tâches, Calendrier, Agents, Knowledge Base, Analytics, Settings.

### Dashboard

Le dashboard ne doit pas être une collection de KPI génériques.

Il doit répondre à :
- Quels leads nécessitent une action ?
- Quels mandats risquent de dormir ?
- Quel suivi client est en retard ?
- Quel agent a proposé une action à valider ?
- Où le pipeline perd du temps ?

### Conversations

Cœur produit.

Règles :
- Inbox claire, assignation visible, statut explicite.
- Résumé IA lisible mais secondaire au message humain.
- Suggestions agent toujours distinguées des messages réels.
- Actions sensibles avec validation humaine.
- Historique et contexte accessibles sans changer d’écran.

### Pipeline

- Kanban sobre, orienté opportunités immobilières.
- Cartes avec contact, bien, valeur/mandat si connu, prochaine action, urgence.
- Pas de colonnes fantaisistes. Chaque statut doit aider à décider.

### Agent runtime

Les agents doivent apparaître comme une couche de contrôle, pas comme des personnages.

Afficher :
- intention détectée
- action proposée
- niveau de confiance
- source/contexte
- bouton approuver / modifier / refuser
- audit log

## 4. Composants clés

### Cards

Chaque card doit porter une décision : lead à traiter, action à valider, mandat à relancer, message à classer.

Structure : titre court, contexte, statut, prochaine action, métadonnée utile.

### Tables

- Denses mais calmes.
- Colonnes limitées.
- Filtres visibles.
- Bulk actions seulement quand elles servent un vrai workflow.

### Forms

- Champs groupés par logique métier.
- Labels explicites, pas de jargon technique.
- Validation immédiate mais discrète.
- Sauvegarde claire.

### Empty states

Jamais “No data”.

Toujours :
- ce qui manque
- pourquoi c’est important
- l’action suivante

Exemple : “Aucun canal connecté. Connectez WhatsApp pour transformer les messages entrants en leads qualifiés.”

### Modales

Réservées aux actions focalisées : validation, création rapide, confirmation risquée.

Pas de modales longues pour des workflows complexes.

## 5. Règles UX

- Le produit part des conversations, pas des dashboards.
- Toute action agentique doit être compréhensible, approuvable et traçable.
- Le vocabulaire doit parler immobilier : lead, mandat, visite, acquéreur, propriétaire, relance, estimation, dossier.
- Le client doit savoir quoi faire en moins de 5 secondes sur chaque écran.
- Les états critiques doivent être visibles sans fouiller.
- Le système doit réduire la charge mentale, pas ajouter une couche d’IA floue.

## 6. Motion

Motion discrète : transitions de panels, hover states, validation d’action, apparition de suggestions.

À éviter : animations permanentes, blobs, lueurs IA, mouvements décoratifs.

Principe : la motion sert à comprendre le changement d’état.

## 7. Accessibilité

- Contraste élevé sur textes/actions.
- Targets cliquables minimum 40px.
- États focus visibles.
- Couleur jamais seule porteuse de sens.
- Texte secondaire lisible, surtout dans inbox et pipeline.

## 8. Anti-patterns interdits

- Chatbot au centre de tout.
- “AI assistant” comme produit principal.
- Dashboard générique avec faux KPIs.
- Gradients violet/bleu SaaS génériques.
- Trop d’icônes, trop de badges, trop de bruit.
- UI qui fonctionnerait pareil pour une startup RH, finance ou e-commerce.
- Vocabulaire abstrait : “optimize workflows”, “boost productivity” sans cas immobilier.

## 9. Références d’intention

- Linear : densité maîtrisée, clarté opérationnelle.
- Vercel : sobriété, hiérarchie, confiance technique.
- Stripe : précision, surfaces propres, documentation implicite.

Mais VividFlow doit rester plus immobilier, plus opérationnel, plus suisse, moins horizontal.

## 10. Quality gate

Un écran VividFlow est validé seulement si :

- il ressemble à un outil que paierait une agence immobilière suisse
- il aide à traiter conversations, leads, mandats ou actions agents
- l’orange signale quelque chose d’important
- l’agentique est permissionné et auditable
- l’interface ne dépend pas d’un effet visuel pour paraître premium
- un utilisateur comprend la prochaine action rapidement
- le design ne pourrait pas être confondu avec un template IA SaaS générique
