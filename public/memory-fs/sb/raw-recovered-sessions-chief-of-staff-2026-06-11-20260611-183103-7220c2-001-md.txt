SOPs et Playbook c'est quoi la différence

## assistant — 2026-06-11T18:31:17.926501

Un **SOP** = la procédure exacte pour exécuter une action.

Un **Playbook** = le guide de décision pour gérer un type de situation.

Exemple simple :

**SOP**
- “Comment publier un carousel LinkedIn”
- Étape 1 : ouvrir Figma
- Étape 2 : exporter en PNG
- Étape 3 : uploader sur LinkedIn
- Étape 4 : vérifier le rendu

C’est une checklist. Peu d’interprétation.

**Playbook**
- “Que faire quand on prépare une campagne LinkedIn”
- Quel angle choisir ?
- Quel type de post selon l’objectif ?
- Qui valide ?
- Quand utiliser un carousel vs un post texte ?
- Que faire si la créa est faible ?
- Quels standards qualité appliquer ?

C’est un cadre d’action. Il contient souvent plusieurs SOPs.

La hiérarchie propre :

**Playbook → Process → SOP**

Ou dans Data OS :

**Système → Process → Étape → SOP**

Donc :

- **Playbook** : “comment on joue la partie”
- **Process** : “dans quel ordre le flux avance”
- **SOP** : “comment faire précisément cette étape”

Pour VividFlow, je ferais :
- **Playbooks** pour les grands cas : acquisition, delivery client, production contenu, gestion agent.
- **SOPs** uniquement pour les tâches critiques répétables : publier, onboarder, QA, envoyer un livrable, traiter un lead.
