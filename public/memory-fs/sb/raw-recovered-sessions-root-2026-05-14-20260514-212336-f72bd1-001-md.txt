4. **Fallback audio → Whisper seulement si nécessaire**
 - Si pas de sous-titres ou blocage complet.
 - Audio via `yt-dlp`, transcription via OpenAI Whisper / Groq / Deepgram.
 - Plus lent mais robuste.

5. **Job async**
 - Ne jamais bloquer l’UI.
 - L’utilisateur voit : “Transcript en génération”.
 - Progression : `queued → fetching_subtitles → transcribing_audio → ready`.

## Implémentation MVP

### Table Convex

```ts
transcriptJobs: defineTable({
 userId: v.string(),
 workspaceId: v.id("workspaces"),
 url: v.string(),
 platform: v.string(),
 videoId: v.string(),
 language: v.optional(v.string()),

 status: v.union(
 v.literal("queued"),
 v.literal("fetching_subtitles"),
 v.literal("transcribing_audio"),
 v.literal("ready"),
 v.literal("failed")
 ),

 source: v.optional(v.union(
 v.literal("cache"),
 v.literal("youtube_transcript_api"),
 v.literal("yt_dlp"),
 v.literal("whisper")
 )),

 transcriptText: v.optional(v.string()),
 segments: v.optional(v.array(v.object({
 start: v.number(),
 duration: v.optional(v.number()),
 text: v.string(),
 }))),

 error: v.optional(v.string()),
 createdAt: v.number(),
 updatedAt: v.number(),
})
.index("by_video", ["platform", "videoId", "language"])
.index("by_workspace", ["workspaceId"])
```

## Le point clé pour éviter les blocages

Le VPS est souvent bloqué parce que YouTube détecte une IP datacenter.

Donc en prod :

```env
YTSCRAPE_WEBSHARE_USER=xxx
YTSCRAPE_WEBSHARE_PASS=xxx
YTSCRAPE_WEBSHARE_COUNTRIES=us,gb,fr
OPENAI_API_KEY=xxx
```

Et côté worker :
- timeout court sur les captions
- retry avec proxy
- fallback Whisper
- cache obligatoire
