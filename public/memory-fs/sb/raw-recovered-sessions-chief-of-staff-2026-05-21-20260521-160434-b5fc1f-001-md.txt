Mais il est encore trop “tech”. Pour un SaaS à 1000 clients, le vrai sujet n’est pas le code : 
**c’est l’économie unitaire + les abus + les jobs longs.**

## Ce qui est très bien dans le brief

- Pas de “génération illimitée”.
- Crédits + hard cap par plan.
- Sonnet réservé aux tâches à valeur.
- Gemini/Haiku pour tâches simples.

- Dashboard admin coût/marge.
- Validation étape par étape dans Claude Code.

## Ce qu’il faut améliorer

### 1. Ne pas parler de “credits” seulement

Les clients comprennent mieux :

- vidéos analysées
- content packs générés
- workspaces clients
- chaînes surveillées
- sièges équipe

Exemple plus vendeur :

```txt
1 vidéo analysée
→ insights + angles + hooks

1 content pack
→ LinkedIn post + X thread + newsletter snippet + carousel outline
```

Les crédits restent en interne.

### 2. Ajouter des limites produit visibles

Le brief dit 2 000 / 5 000 / 10 000 credits. 
Mais il faut traduire ça en usage simple.

Exemple :

**Starter 99€**
- 1 workspace
- 2 chaînes YouTube
- 25 vidéos analysées/mois
- 150 contenus générés/mois

**Agency 199€**
- 5 workspaces clients
- 10 chaînes YouTube
- 75 vidéos analysées/mois
- 500 contenus générés/mois
- approval workflow

Sinon l’utilisateur ne sait pas ce qu’il achète.

### 3. Le module worker PM2 est fragile

Pour MVP, ok. 
Pour 1000 utilisateurs, attention.

Il faut une vraie logique de queue :

```txt
queued → processing → retrying → completed / failed
```

À ajouter :
- idempotency key
- retry max
- dead-letter queue
- timeout par job
- remboursement crédit si échec réel
- limite de jobs simultanés par workspace

PM2 seul ne suffit pas comme garantie produit.

### 4. Ajouter un hard cap plateforme

Le brief prévoit hard cap par workspace. Bien.

Mais il faut aussi :

```txt
hard cap global jour/mois côté plateforme
```

Exemple :
- alerte à 150€/jour
- blocage partiel à 300€/jour
- coupure modèles premium si dérive

Sinon 20 clients qui abusent en même temps peuvent faire mal.

### 5. Le cache cross-client doit être très strict

Cache global autorisé uniquement pour :

- transcription vidéo publique
- metadata YouTube publique
- insights bruts génériques
- résumé neutre de vidéo publique

Jamais dans le cache global :
- brand voice client
- prompts personnalisés
- posts finaux
- données workspace
- historique client

Sinon risque de fuite inter-client.

### 6. Free trial à verrouiller

Gros signal Reddit : les SaaS IA se font exploser par les trials gratuits.

Reco :
- pas de trial illimité
- pas de génération massive sans carte
- trial limité à :
 - 3 vidéos analysées
 - 10 outputs
 - exports limités

Ou mieux :
**audit gratuit**, génération complète après paiement.

### 7. Éviter le mot “unlimited”

À proscrire partout :
```txt
unlimited generations
unlimited content
unlimited AI
```

Même sur les plans chers.

Dire plutôt :
```txt
usage généreux
packs inclus
overage disponible
limites transparentes
```
