# 5. Ce qu’il ne faut pas faire

Ne pas faire :

```txt
Next.js appelle directement un Hermes global
```

Parce que ça crée un monstre :

- toutes les sessions mélangées
- mémoire globale dangereuse
- filesystem partagé
- secrets en vrac
- agent potentiellement capable d’accéder à tout
- aucune isolation client

Ne pas faire non plus :

```txt
un seul HERMES_HOME pour tous les clients
```

Il faut au minimum :

```txt
HERMES_HOME=/data/hermes/{workspaceId}
```

ou mieux :

```txt
container dédié + volume dédié
```

# 11. Le point sécurité majeur

Le plus gros risque vu dans GitHub/Reddit : **l’agent ne doit jamais voir les vrais secrets**.

Mauvais :

```env
GITHUB_TOKEN=...
STRIPE_SECRET=...
SUPABASE_SERVICE_KEY=...
```

dans le container agent.

Bon :

```txt
Agent → demande action
Credential Proxy → injecte secret côté host
API externe → réponse
```

Donc :

- secrets chiffrés côté SaaS
- proxy de credentials
- tokens courts
- scopes précis
- audit complet
- jamais de secrets bruts dans le prompt, logs, env agent
