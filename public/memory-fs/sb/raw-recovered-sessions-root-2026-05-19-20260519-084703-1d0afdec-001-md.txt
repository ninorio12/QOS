## Objectif d’un appel de découverte VividFlow

Un appel de découverte ne sert pas à vendre l’IA.

Il sert à comprendre :
- comment l’entreprise fonctionne vraiment
- où le dirigeant perd du temps
- quels process bloquent la croissance
- où l’automatisation peut créer un impact rapide
- si le prospect est prêt à avancer sur une démo ou une proposition concrète

La vente vient après. D’abord, on diagnostique.

---

## 1. La posture à avoir

### Posture principale : consultant, pas vendeur

Le commercial doit se positionner comme quelqu’un qui analyse le business du prospect, pas comme quelqu’un qui pousse une solution.

À retenir de Minozan :
- il pose beaucoup de questions
- il laisse le prospect parler
- il reformule souvent
- il relie les réponses à des enjeux business
- il ne rentre pas trop vite dans la technique
- il vend une transformation opérationnelle, pas “de l’IA”

Phrase-type :

> “L’objectif, c’est d’abord de comprendre vos process, voir où vous perdez du temps, et ensuite seulement voir si une solution agentique peut vraiment vous aider.”

---

## 2. La structure idéale de l’appel

### Étape 1 — Cadrer l’appel

Objectif : rassurer et poser le cadre.

À dire :
- “On va faire un diagnostic de votre activité.”
- “L’objectif n’est pas de vous vendre quelque chose tout de suite.”
- “Si c’est pertinent, on fera un deuxième appel avec une démonstration concrète.”

Pourquoi c’est important :
- ça baisse la résistance commerciale
- ça montre qu’on est sérieux
- ça prépare naturellement le prochain rendez-vous

---

### Étape 2 — Comprendre l’activité

Questions à poser :
- “Vous pouvez me résumer votre activité au quotidien ?”
- “Qui sont vos clients principaux ?”
- “Comment votre équipe est structurée aujourd’hui ?”
- “Quels outils utilisez-vous déjà ?”
- “Qu’est-ce qui prend le plus de temps dans votre journée ?”

Dans l’appel, ça a permis d’identifier :
- 2000 clients en gestion
- 1450 clients privés
- 560 entreprises
- 2 personnes au back-office
- un logiciel métier existant : Brokinsoft
- une grosse charge sur les sinistres, mails, appels d’offres et comparatifs

---

### Étape 3 — Identifier les tâches chronophages

Le but est de faire parler le prospect sur ce qui l’empêche d’avancer.

Questions clés :
- “Aujourd’hui, qu’est-ce qui vous bloque le plus ?”
- “Quelles tâches reviennent tous les jours ?”
- “Qu’est-ce que vous aimeriez déléguer si vous aviez quelqu’un en plus ?”
- “Qu’est-ce qui vous empêche de faire plus de commercial ?”
- “Quelles tâches sont importantes mais ne génèrent pas directement de revenu ?”

Dans l’appel, le point fort est sorti clairement :

> Le dirigeant passe trop de temps sur les sinistres et les emails, alors que son vrai levier de croissance est d’être sur le terrain avec ses clients.

C’est exactement ce qu’on doit chercher.

---

### Étape 4 — Quantifier le problème

Un bon appel de découverte doit transformer un problème flou en problème mesurable.

Questions à poser :
- “Combien de mails recevez-vous par jour ?”
- “Combien de demandes par semaine ?”
- “Combien de temps ça prend ?”
- “Combien coûterait une personne pour faire ça ?”
- “Quel est le coût si rien ne change ?”

Dans l’appel, les chiffres importants :
- 50 à 60 emails par jour
- environ 60 % liés aux sinistres
- 4 à 5 appels d’offres par semaine
- jusqu’à 1 mois pour produire certains tableaux comparatifs
- un employé back-office coûte environ 7000 à 7500 CHF/mois charges comprises
- turnover tous les 2 ans environ sur le back-office

Ces chiffres donnent de la valeur à la solution.

On ne vend plus “un agent IA”.

On vend :
- du temps récupéré
- moins de dépendance au recrutement
- moins de surcharge opérationnelle
- plus de capacité commerciale
- plus de réactivité client

---

### Étape 5 — Comprendre le modèle économique

Il faut comprendre comment le client gagne de l’argent.

Questions à poser :
- “Qu’est-ce qui génère vraiment du revenu chez vous ?”
- “Quelles tâches sont nécessaires mais non facturées ?”
- “Où est la marge ?”
- “Où est la perte de temps ?”
- “Si vous aviez plus de temps, qu’est-ce que vous feriez pour développer l’activité ?”

Dans l’appel, on comprend que :
- la gestion des sinistres est essentielle pour fidéliser
- mais elle ne génère pas directement de revenu
- le dirigeant doit être plus sur le terrain pour développer le portefeuille
- chaque heure passée en back-office l’éloigne du développement commercial

C’est le cœur du diagnostic.

## 3. Les questions puissantes à retenir

### Question 1 — Le “monde idéal”

Très bonne question de Minozan :

Pourquoi c’est puissant :
- le prospect décrit lui-même la solution idéale
- ça permet de mapper les futurs agents IA
- ça évite de vendre une solution générique

Réponse obtenue dans l’appel :
- une personne back-office entreprise
- une personne back-office privé/PME
- une personne dédiée aux sinistres
- une chef de bureau
- le dirigeant concentré sur le commercial

Ça donne directement l’architecture potentielle des agents.

Très bonne question :

> “Qu’est-ce qui fait que c’est devenu prioritaire maintenant ?”

Pourquoi c’est important :
- ça qualifie le timing
- ça évite les prospects curieux mais pas acheteurs
- ça révèle la vraie douleur

Réponse obtenue :
- difficulté à recruter
- turnover fréquent
- surcharge emails
- besoin de gagner du temps
- envie d’utiliser l’IA concrètement

### Question 3 — Le coût de l’alternative

Très bonne question :

> “Si vous deviez recruter une personne en plus, ça coûterait combien ?”

Pourquoi c’est puissant :
- ça crée un point de comparaison
- ça rend l’offre VividFlow plus rationnelle
- ça permet de parler ROI sans forcer

Réponse obtenue :
- environ 7000 à 7500 CHF/mois pour un 100 %

À retenir pour les commerciaux :

> Toujours comparer l’agent IA au coût d’un recrutement, pas seulement au prix d’un logiciel.

Question importante :

Réponse du prospect :

- pas assez concret
- aucune démo
- pas de visualisation claire de la valeur

Leçon commerciale énorme :

> Les prospects ne veulent pas qu’on leur explique l’IA. Ils veulent voir concrètement ce que ça peut faire dans leur business.

## Pourquoi

Un chat dans un SaaS doit pouvoir :
- répondre dans ton interface
- gérer plusieurs utilisateurs
- être appelé depuis ton backend
- avoir des logs
- être sécurisé
- être facturable / mesurable
- fonctionner sans ton compte personnel ouvert

Donc là, l’API est le bon outil.

---

## Ce que ça coûterait

Pour un chat SaaS interne / équipe, ça peut rester raisonnable.

### Si le chat est peu utilisé
Exemple : toi + Thomas + quelques tests.

Coût probable :
**5 à 30$/mois**

### Si le chat est utilisé tous les jours par l’équipe
Coût probable :
**30 à 150$/mois**

### Si le chat est ouvert aux clients
Là, ça dépend du nombre d’utilisateurs.

Mais tu peux contrôler avec :
- limite de messages par jour
- limite par workspace
- modèle cheap par défaut
- modèle fort seulement sur demande
- historique résumé au lieu d’envoyer toute la conversation
- budget cap

---

## Reco pour ton SaaS

Pour intégrer un chat dans le Data OS / SaaS VividFlow :

### 1. API obligatoire
Créer une clé API dédiée à VividFlow.

Pas ta clé perso. 
Pas une clé partagée n’importe comment.

### 2. Backend uniquement
La clé ne doit jamais être dans le frontend.

Elle doit être côté serveur :
- API route Next.js
- Convex action
- serveur backend
- edge/serverless sécurisé

### 3. Modèle low-cost par défaut
Le chat ne doit pas utiliser le modèle premium sur chaque message.

Architecture :
- modèle cheap pour répondre vite / simple
- modèle premium seulement pour analyse complexe

### 4. Limites par utilisateur
Mettre dès le début :
- messages/jour
- tokens max
- taille d’historique max
- budget max par workspace
- logs de consommation

### 5. Mémoire contrôlée
Ne pas renvoyer toute l’historique à chaque fois.

Faire :
- résumé de conversation
- contexte utile
- derniers messages seulement
- documents pertinents seulement

---

## Structure simple

Pour le SaaS :

```text
Frontend Chat UI
→ API Route sécurisée
→ Vérification utilisateur / workspace
→ Récupération contexte utile
→ Appel OpenAI API
→ Réponse streamée
→ Log coût + message
```
