# Brvndlab — Product OS

Brvndlab est cadré comme un **Content OS / Brand OS privé** pour produire du contenu vite, avec profondeur, et piloter la boucle contenu → audience → leads → cash.

## Modules cœur validés

- **Brand OS** : source de vérité de la marque.
- **Content** : production depuis cette vérité.
- **Brainstormer** : sparring partner pour angles, positionnement, conversion et perspectives.
- **Calendar / Pipeline** : organisation et suivi de production.
- **Smart Links / Leads / Stripe / Whop** : lecture attraction → conversion → vente.

## Brainstormer — état produit

Le Brainstormer doit rester prioritaire : l’ancienne interface existait, mais `/api/brainstorm-explore` devait être rebranché pour que Lya réponde réellement.

À préserver dans les cartes de brainstorm :
- idée centrale ;
- point fort ;
- perspective / alignement ;
- tension / problème ;
- ce qu’on peut en faire ;
- transcript caché accessible au slide.

## Transformations après brainstorm

Décision du 2026-06-13 : simplifier les boutons de transformation en bas de carte.

À garder actifs :
- Script ;
- Story ;
- Carrousel ;
- Post.

À garder désactivé avec badge **Bientôt** :
- Lead magnet.

À supprimer :
- Email ;
- Questions audience.

## Règles produit

- D’abord l’idée / l’angle, ensuite le format.
- Ne pas remettre un module email tant que le destinataire et l’usage ne sont pas clairs.
- Ne pas prioriser Question audience dans ce flow : hors besoin immédiat.
- Ne pas modifier la logique principale du Brainstormer ni les données existantes en nettoyant les boutons.

## Environnement de dev — signal opérationnel

## Claude sharp — garde-fous à privilégier

Améliorations techniques validées pour rendre Claude plus rapide et fiable sur Brvndlab :

- launcher dédié type `brvndlab-claude` qui ouvre directement le repo canonique ;
- safety check avant action : blocage si chemin iCloud/Documents, secrets ou commande trop large ;
- scripts projet courts : `guard:repo`, `check:fast`, `check:lint`, `check:prod-risk`, `smoke` ;
- timeout sur commandes longues ;
- missions petites et vérifiables, puis résultat essentiel seulement ;
- clone canonique côté Hermes à envisager si SSH Mac devient un frein.
