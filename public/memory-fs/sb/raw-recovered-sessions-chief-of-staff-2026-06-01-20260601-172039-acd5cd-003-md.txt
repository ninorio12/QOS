### GBrain
C’est la mémoire active des agents :
- recherche contexte
- relations clients/offres/personnes
- scopes d’accès
- contexte injecté automatiquement avant réponse
- graphe entreprise

## Répartition nette

```text
Data OS = ce qu’on fait
Second Brain = ce qu’on sait
GBrain = ce que les agents peuvent retrouver/utiliser
Slack = où l’équipe agit
Telegram = où la direction décide
```

## Ma recommandation

On ne choisit pas “Karpathy OU GBrain”.

On fait :

1. **Second Brain comme socle lisible**
 - fichiers Markdown
 - propre
 - auditable
 - versionnable

2. **GBrain comme moteur agentique**
 - recherche
 - graph
 - scopes
 - injection contexte

3. **Data OS comme cockpit business**
 - tâches
 - décisions
 - clients
 - statuts

## Le vrai flux

Exemple :

Thomas dit dans Telegram :
> “On doit repositionner VividFlow pour PME suisses.”

Moi :
1. Je garde la discussion privée.
2. Si validé, je pousse dans Slack :
```text
@Strategy Propose 3 angles de repositionnement PME Suisse.
@CMO Prépare 5 hooks LinkedIn basés sur ces angles.
@Operations Crée une tâche Data OS : repositionnement offre PME.
```
3. Les agents bossent.
4. Les décisions validées vont dans Data OS.
5. La doctrine finale va dans Second Brain.
6. GBrain indexe pour que les agents la retrouvent plus tard.

## Décision claire

Pour VividFlow, on doit construire :

```text
Chief of Staff Telegram
+ Coordinator Slack
+ 4 agents métiers
+ Data OS
+ Second Brain Markdown
+ GBrain en moteur mémoire/scopes
```

C’est ça le système propre.
