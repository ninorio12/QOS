# VividFlow Slack extension gateway

## Signal validé — 2026-06-15

Le profil Hermes `vividflow-slack-extension` a été validé comme extension Slack du Coordinateur : gateway Slack actif, service systemd installé en 24/24, linger activé, DM Slack fonctionnel et provider corrigé vers `openai-codex` / `gpt-5.5`.

Méthode durable :
1. Créer ou réparer un profil Hermes séparé pour Slack, sans mélanger Telegram/WhatsApp.
2. Neutraliser les variables Telegram/WhatsApp du profil Slack si elles polluent le gateway.
3. Configurer Slack Events/Socket Mode, `message.im`, `app_mention`, scopes nécessaires, puis réinstaller l’app.
4. Mettre à jour l’allowlist Slack si le user de test est rejeté.
5. Corriger le provider/modèle avant validation : éviter OpenRouter si crédits insuffisants; cible validée ici = `openai-codex` + `gpt-5.5`.
6. Tester DM + mention channel avant installation 24/24.
7. Installer le gateway en service user systemd et vérifier `running` + linger.

Garde-fous :
- ne jamais recopier les tokens `xapp-*` / `xoxb-*` dans le wiki;
- ne pas exposer logs techniques sensibles;
- Telegram reste cockpit humain, Slack reste extension/exécution interne;
- si Data OS refuse l’écriture avec `Unauthorized: token agent requis`, le skill local peut être sauvegardé mais n’est pas encore poussé dans Data OS Knowledge.
