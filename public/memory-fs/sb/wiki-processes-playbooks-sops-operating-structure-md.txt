# Playbooks / Process / SOPs — structure opérationnelle

## Règle

Un **playbook** est un guide de décision pour gérer un type de situation.
Une **SOP** est la procédure exacte pour exécuter une action répétable.

Hiérarchie VividFlow :
- **Système** : domaine complet à piloter.
- **Playbook** : comment jouer la situation, choisir l’angle, arbitrer et valider.
- **Process** : ordre du flux de travail.
- **SOP** : checklist précise d’une étape critique.

## Usage

Créer des playbooks pour les grands cas : acquisition, delivery client, production contenu, gestion agent.
Créer des SOPs uniquement pour les tâches critiques répétables : publier, onboarder, QA, envoyer un livrable, traiter un lead.

Règle anti-complexité : ne pas transformer chaque idée en SOP. Une SOP doit réduire l’ambiguïté d’exécution, pas documenter une réflexion.


## Data OS — cadre d’action agents

Les agents ne doivent pas seulement avoir un prompt. Ils doivent avoir un cadre d’action dans le Data OS :
- **SOPs** : procédures fixes/checklists exécutables ;
- **Playbooks** : guides de décision selon contexte ;
- **Skills** : capacités techniques réutilisables ;
- **Permissions** : ce que chaque agent peut lire, proposer, exécuter, approuver ou jamais faire.

À créer dans le Data OS : base SOPs, base Playbooks, liaison SOP/Playbook ↔ agent ↔ tâche ↔ log, revue périodique, audit trail quand un agent suit ou ignore une procédure.
