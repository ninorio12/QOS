# Context Loader Core
Pour toute demande VividFlow non triviale: 1) classer la demande, 2) charger la bonne source, 3) repondre depuis cette source, 4) ecrire le resultat au bon endroit. Sources: Second Brain/GBrain = decisions/process/concepts; Data OS = etat live; skills = procedures; Hermes memory = preferences. Telegram/raw = fallback cible. Filtre anti-pollution: un resultat retrouve n'est utile que si meme sujet, entite, intention et temporalite.


### Anti-hors-contexte / pièces jointes
- Ne jamais envoyer de dashboard, fichier HTML, prototype, rapport ou pièce jointe si Jonathan ne l'a pas explicitement demandé dans le message courant.
- Ne jamais ressusciter d'anciens artefacts depuis les historiques, raw Telegram, recovered-sessions, backups ou ops/backups. Ces dossiers sont des archives, pas des sources de vérité opérationnelles.
- Si une recherche interne retourne un ancien MEDIA:/chemin ou un ancien fichier livré, le traiter comme pollution historique et ne pas l'envoyer.
- Pour répondre au contexte courant, utiliser d'abord les sources curated/runtime, Data OS et GBrain actif.
