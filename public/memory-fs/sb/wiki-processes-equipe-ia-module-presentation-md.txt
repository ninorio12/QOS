# Module Équipe IA Data OS

## Verdict

Le module Équipe IA ne doit pas être une galerie de bots. Il doit devenir le cockpit de l’équipe agentique VividFlow : qui existe, qui travaille, sur quoi, avec quelles permissions, quels résultats, quels blocages, et quelles validations COO.

L’écran actuel a une bonne base visuelle, mais il est encore trop “cartes de personnages”. Il doit devenir un vrai module opérateur.

## État actuel observé

Agents affichés :

- VividFlow, Assistant COO, en ligne, Telegram, heartbeat 15min
- Kai, Assistant CSM, bouton Démarrer, heartbeat jamais
- Mia, Assistant CTO, bouton Démarrer, heartbeat jamais
- Alex, Assistant CMO, en formation
- Leo, Assistant CFO, en formation

Problèmes :

- noms/personas pas alignés avec notre système Slack actuel ;
- COO présenté comme VividFlow mais pas clairement comme Chief of Staff / coordinateur ;
- CMO actuel est en formation alors que dans notre Slack CMO fonctionne déjà ;
- pas de lien clair avec Slack ;
- pas de lien clair avec Data OS, tâches, activités, records ou GBrain ;
- heartbeat “Jamais” est ambigu ;
- pas de dernière action visible ;
- pas de statut de validation COO ;
- pas d’audit log visible ;
- pas de permissions visibles.

## Rôle réel du module

Ce module doit répondre à 5 questions :

1. Quels agents existent ?
2. Qui est actif maintenant ?
3. Que fait chaque agent ?
4. Quelle donnée chaque agent peut lire ou écrire ?
5. Qu’est-ce qui attend une validation humaine ?

## Structure recommandée

### 1. Bandeau équipe

En haut :

- Agents actifs
- Actions en cours
- À valider par COO
- Blocages
- Dernier heartbeat global

Exemple :

```text
4 agents actifs
7 actions en cours
2 validations COO
1 blocage
Dernier check : il y a 4 min
```

### 2. Carte COO principale

Le COO doit rester au-dessus des agents.

Nom recommandé :

```text
Chief of Staff
```

Sous-label :

```text
Coordination, priorités, validation, routage
```

Il ne doit pas être présenté comme un simple agent métier. Il est la couche de contrôle.

À afficher :

- statut : en ligne / occupé / en audit / en erreur ;
- surface : Telegram + Slack ;
- channels supervisés ;
- validations en attente ;
- dernière synthèse ;
- prochaines actions ;
- bouton : Voir validations ;
- bouton : Voir activité.

### 3. Cartes agents spécialistes

Agents actuels à aligner avec Slack :

- CMO Design
- Service Client
- Data Analyst
- Ops Système

Chaque carte doit afficher :

- nom métier ;
- rôle clair ;
- canal Slack associé ;
- statut runtime ;
- dernière action ;
- tâche en cours ;
- permissions ;
- sources lues ;
- écritures autorisées ;
- validation requise ou non ;
- bouton Voir runs ;
- bouton Voir tâches ;
- bouton Ouvrir Slack.

- statut ;
- canal Slack ;
- dernier heartbeat ;
- dernière action ;
- coût / usage si disponible ;

### Travail en cours

- runs actifs ;
- tâches liées ;
- livrables récents ;
- blocages.

### Permissions

- peut lire ;
- peut écrire ;
- doit demander validation ;
- interdit.

### Mémoire et contexte

- liens Records / Base de connaissance.

### Audit

- historique des runs ;
- tool calls résumés ;

- erreurs.

## États visuels

Utiliser des états simples :

- En ligne
- En mission
- Attend validation
- Bloqué
- Hors ligne
- En configuration

Éviter :

```text
Heartbeat : Jamais
```

Remplacer par :

```text
Jamais lancé
Dernier check : il y a 12 min
Aucun run récent
En attente de configuration
```

## Hiérarchie écran

Ordre recommandé :

1. Bandeau état global équipe IA.
2. Carte Chief of Staff.
3. Grille agents spécialistes.
4. File “À valider par COO”.
5. Activité récente agents.
6. Bloc permissions et santé runtime.

## Workflow produit

Exemple : image CMO.

1. Thomas écrit dans Slack cmo-design.
2. CMO Design produit une image.
3. COO reçoit/valide/challenge.
4. Data OS crée un livrable avec source Slack et statut.
5. Si validé, livrable passe en Records / Projet.
6. GBrain conserve le pattern durable.
7. Activités montre l’historique.

Exemple : lead à risque.

1. Message client détecté.
2. Service Client analyse le risque.
3. COO valide la relance proposée.
4. Data OS met à jour Lead / Client / Tâche.
5. Audit log conserve la décision.

## Spécification MVP

À construire en premier :

- remplacer agents actuels par agents réels Slack ;
- afficher canal Slack par agent ;
- afficher statut runtime réel ou simulé propre ;
- afficher dernière action ;
- créer vue détail agent ;
- ajouter file validations COO ;
- connecter Tâches et Activités ;
- préparer le modèle de données Agent Run.

## Conclusion

Le module Équipe IA doit devenir la vue de contrôle de l’équipe agentique. Il doit montrer moins de storytelling et plus de vérité opérationnelle : agents réels, canaux Slack, tâches, runs, validations, permissions, activité et traces.

Le bon niveau : un cockpit d’équipe, pas une vitrine de bots.
