## assistant — 2026-05-18T12:24:46.573195

Oui, c’est possible — mais il faut distinguer **même Vercel project** vs **même prod**.

La bonne architecture :

- **Plusieurs agents peuvent bosser en parallèle sur le même repo**
 - chacun sur sa branche Git
 - chacun ouvre une PR
 - Vercel génère un **Preview Deployment** par branche/PR
 - on teste chaque preview séparément

- **Un seul agent/orchestrateur doit contrôler la prod**
 - merge vers `main`
 - deploy `--prod`
 - vérification domaine canonique
 - rollback si besoin

Ce qu’il faut éviter absolument :

- Plusieurs agents qui modifient la même branche `main`
- Plusieurs agents qui lancent `vercel deploy --prod` en même temps
- Plusieurs agents qui travaillent dans le même dossier local avec un `.vercel/project.json` partagé sans contrôle
- Un agent qui relink Vercel (`vercel link`) pendant qu’un autre déploie

Setup recommandé pour nous :

1. **1 repo source**
2. **1 projet Vercel prod**
3. **1 branche par agent**
 - `agent/ui-dashboard`
 - `agent/convex-schema`
 - `agent/onboarding-flow`
4. **Preview Vercel automatique par PR**
5. **Cockpit / orchestrateur décide quoi merger**
6. **Prod uniquement via main**

Si on veut faire ça proprement avec Hermes :

- Chaque agent peut avoir son propre profil/mémoire/rôle.
- Ils peuvent partager le même accès Vercel/GitHub.
- Mais il faut leur imposer une règle : **jamais de prod deploy direct sauf agent désigné**.

Donc réponse courte : 
**Oui, plusieurs agents peuvent travailler simultanément sur le même Vercel, mais uniquement via branches + previews. La prod doit rester verrouillée derrière un orchestrateur unique.**
