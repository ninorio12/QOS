## 1. Un topic Telegram

Un **topic**, c’est surtout une *salle de discussion*.

Exemple :

- Topic “Tech”
- Topic “Tracker”
- Topic “SaaS Developer”
- Topic “CMO”
- Topic “Finance”

- contexte séparé par sujet

- même identité visible Telegram
- mémoire moins isolée sauf si on configure bien

**Un topic = une pièce / un canal de travail.**

Oui, c’est possible.

Mais il y a deux manières.

## Mauvaise manière

Les bots se parlent librement dans Telegram.

Risque :

- bruit énorme
- discussions infinies
- confusion
- hallucination collective
- perte de contrôle
- personne ne sait qui décide

À éviter.

## Bonne manière

Ils discutent **via le Data OS / Kanban**, pas en freestyle.

Exemple :

```text
Thomas donne une tâche
→ Cockpit la transforme en mission
→ Data OS crée une task
→ Agent Product analyse
→ Agent Tech reçoit un brief structuré
→ Agent Developer exécute
→ Agent Reviewer vérifie
→ Cockpit synthétise
→ Thomas reçoit seulement la décision utile
```

Les agents peuvent se transmettre :

- brief
- contexte
- blocage
- artefact
- décision demandée
- preuve
- review

Mais tout est tracé.

# Le bon modèle de discussion entre agents

Je recommande ça :

```text
Cockpit = orchestrateur
Data OS = source de vérité
Agents = workers spécialisés
Kanban = tâches et statuts
Audit log = preuve
Telegram topics = interface humaine
```

Donc les agents “discutent”, mais sous forme de **handoffs structurés** :

```text

```

Puis :

```text

Fait:
Preuves:
Tests:
Blocages:
Décision nécessaire:
```

Ça évite le chaos.
