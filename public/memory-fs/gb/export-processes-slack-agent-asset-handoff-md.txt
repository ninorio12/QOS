# Slack agent asset handoff

Règle opérationnelle VividFlow :

1. La mission envoyée aux agents Slack doit être en langage naturel, claire, non bridée; courte si possible, mais pas au prix du sens.
2. Utiliser JSON seulement quand cela clarifie un livrable structuré, jamais comme contrainte artificielle.
3. Le COO orchestre dans Slack : il brief, récupère la sortie, challenge, demande correction si nécessaire.
3. Pour les assets visuels, le CMO produit l'image ou le prompt/asset via ses outils visuels. Le COO ne doit pas se substituer au CMO sauf fallback explicite.
4. Le COO valide l'asset final : qualité, cohérence VividFlow, absence de texte/logos indésirables, utilité business.
5. Une fois validé, le COO remonte uniquement le résultat final dans Telegram/cockpit, pas les échanges internes.
6. Si un pattern fonctionne, il est classé dans GBrain/Second Brain pour être acquis et réutilisé automatiquement.

Format Slack recommandé :

```text
Mission: [résultat attendu]
Contrainte: [qualité/format]
Livrable: [image/fichier/texte]
```

Format retour COO vers Telegram :

```text
Validé.
[asset ou fichier]
Point utile: ...
```
