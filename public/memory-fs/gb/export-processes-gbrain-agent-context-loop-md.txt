# Boucle GBrain agents

## Boucle obligatoire

```text
Demande Telegram/Slack
→ COO clarifie et route
→ context loader injecte contexte GBrain
→ agent exécute avec auto-QA
→ agent indique routage mémoire/opérationnel
→ COO challenge
→ GBrain conserve le durable
→ Data OS reçoit l’opérationnel
```

## Avant réponse agent

Chaque agent doit vérifier :

1. Quelles règles GBrain s’appliquent ?
2. Quelle preuve/source existe ?
3. Quelle utilité VividFlow ?
4. Quel risque ou angle mort ?
5. Quelle amélioration possible ?
6. Où router : GBrain / Data OS / R&D / bruit ?

## Rôle COO

Le COO ne délègue pas mécaniquement.
Il vérifie la mention Slack réelle, la réception, la réponse, la conformité, puis pousse une correction si nécessaire.
